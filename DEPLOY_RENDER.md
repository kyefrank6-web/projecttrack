# Deploy ProjectTrack UG on Render with a custom domain

This project includes a [Render Blueprint](https://render.com/docs/blueprint-spec) (`render.yaml`): one **Web Service** (Django + Gunicorn) and one **PostgreSQL** database.

## 1. Push code to GitHub

Render deploys from Git. Commit and push this repository to GitHub (or GitLab/Bitbucket).

## 2. Create the stack on Render

1. Sign in at [render.com](https://render.com).
2. **New → Blueprint**.
3. Connect the repo and apply the blueprint (creates `projecttrack-ug` web service + `projecttrack-ug-db` Postgres).
4. Wait for the first deploy to finish. Open the `*.onrender.com` URL to confirm the site loads.

## 3. Set production secrets (Environment tab)

In the **web service → Environment**, set or update:

| Variable | Purpose |
|----------|---------|
| `SECRET_KEY` | Auto-generated by blueprint; leave as-is unless rotating |
| `DEBUG` | Must be `false` in production |
| `SUPERADMIN_USERNAME` | Platform admin login username |
| `SUPERADMIN_PASSWORD` | **Change** from the blueprint default to a strong password |
| `PRIMARY_DOMAIN` | Your public domain, e.g. `app.yourschool.ac.ug` (no `https://`) |
| `DJANGO_ALLOWED_HOSTS` | Optional extra hosts, comma-separated (`.onrender.com` is already in the blueprint) |
| `CSRF_TRUSTED_ORIGINS` | Optional extra origins if you use additional URLs |

`PRIMARY_DOMAIN` automatically adds that host, `www.` variant, and `https://` CSRF origins in Django settings.

Redeploy after changing environment variables.

## 4. Attach your custom domain on Render

1. Web service → **Settings → Custom Domains → Add custom domain**.
2. Enter the hostname users will visit (e.g. `app.yourschool.ac.ug` or `www.yourschool.ac.ug`).
3. Render shows **DNS records** to add at your domain registrar (Namecheap, Cloudflare, GoDaddy, etc.):
   - **Subdomain** (recommended): usually a **CNAME** pointing to your Render service hostname.
   - **Apex / root** (`yourschool.ac.ug`): follow Render’s **ANAME/ALIAS** or A-record instructions for your DNS provider.
4. Wait for DNS propagation and Render’s certificate (HTTPS). Status should show **Verified**.

Set `PRIMARY_DOMAIN` to the **main** hostname you want in links (match what users type in the browser).

## 5. Email (password reset)

Default email is console-only. For production, configure SMTP on the web service, for example:

- `DJANGO_EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`
- `DJANGO_EMAIL_HOST`, `DJANGO_EMAIL_PORT`, `DJANGO_EMAIL_HOST_USER`, `DJANGO_EMAIL_HOST_PASSWORD`
- `DJANGO_DEFAULT_FROM_EMAIL=ProjectTrack UG <noreply@yourdomain.com>`

## 6. Uploaded files (logos, evidence photos)

On Render, the filesystem is **ephemeral** unless you add storage:

- **Persistent disk** (paid): mount at `/var/data`, set `MEDIA_ROOT=/var/data/media` on the web service.
- Or use **S3-compatible storage** (future enhancement).

Plan uploads accordingly for production.

## 7. Maintenance during updates

Use **Superadmin → Platform administration → System maintenance**, or set `MAINTENANCE_MODE=true` on the server before deploys.

## 8. Useful commands (Render Shell)

```bash
python manage.py migrate
python manage.py create_superadmin --username YOUR_USER --password 'YOUR_PASS'
python manage.py bootstrap_school  # if you use the test-school command locally
```

## Cloudflare in front of Render

1. **SSL/TLS → Overview** → set encryption to **Full** (not Flexible).
2. **DNS** → CNAME `@` and `www` → your `*.onrender.com` hostname.
3. First deploy: set **Proxy status** to **DNS only** (grey cloud) until Render **Custom Domains** shows **Verified**, then you may enable **Proxied** (orange).
4. On Render **Environment**, set `PRIMARY_DOMAIN=yourdomain.ac.ug` and redeploy (fixes **400 Bad Request** on login).

## Troubleshooting

| Issue | Fix |
|-------|-----|
| **400 Bad Request** (plain Django page) | Set `PRIMARY_DOMAIN` on Render to your domain, redeploy |
| **DisallowedHost** | Add host to `PRIMARY_DOMAIN` or `DJANGO_ALLOWED_HOSTS`, redeploy |
| **CSRF verification failed** | Add `https://yourdomain.com` to `CSRF_TRUSTED_ORIGINS` or set `PRIMARY_DOMAIN` |
| **502 / timeout on upload** | Free tier is slow; increase Gunicorn timeout or upgrade plan |
| **Database errors** | Confirm `DATABASE_URL` is linked from the Postgres service |

## Local parity

```bash
pip install -r requirements.txt
export DATABASE_URL=...   # optional; omit for SQLite
export DEBUG=false
export PRIMARY_DOMAIN=app.yourschool.ac.ug
python manage.py migrate
python manage.py runserver
```
